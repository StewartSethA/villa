# Vetting / painting UI: design + label-event schema (2026-10-06)

Status: DESIGN ONLY. The painter is NOT built. Schema: `label_events.schema.json` (this dir). README.md in this dir is the separate survey of what exists; this file is the label/proposal/overlay design.
Source of the requirements: user, relayed by the coordinator 2026-10-06. Nothing below is validated against human annotation (D6; only 2 human selfx verdicts exist, selfx STATE).

## 1. Rules (user requirements)
1. **Minimal human burden. Unlabelled = unknown = masked.** No field requires a label; no segment is blocked, demoted, penalised or counted bad for lacking one; unknown cells are excluded from every loss, metric, gate and leaderboard.
2. **Severable channels, append-only.** Channels: `good_sheet, self_crossing, vacuum, fold, sheet_skip, mushy_low_confidence, unknown`. Each is a sparse per-vertex/cell mask with 3 states `yes / no / unknown`, stored as an event log (who, when, tool version, channel, region, state). A sheet can be GOOD in `good_sheet` while `self_crossing` paint marks defects; painting one channel never implies or erases another; undo = a later event. Current state = last event covering the vertex.
3. **Auto-identification pre-fills PROPOSALS** (distinct colour, one-click accept/reject per region, "accept all in channel"); the human corrects misses and false alarms only. A review queue sorts by detector uncertainty, detector disagreement and size so about 1 minute per segment suffices; label only a subset.
4. **Proposals are the measurement.** Accepted / rejected / edited proposals (`proposal_response`) are exactly the data that measures detector precision and recall per channel. Report (to build with the tool): per channel and detector, n = segments reviewed, n = proposal regions, cells reviewed and cm2 reviewed, precision = accepted/(accepted+rejected), recall on human-added regions, with bootstrap CI over SEGMENTS. Caveats to print: reviewers see the proposal (anchoring bias; recall of human-added regions is a lower bound on misses); unreviewed segments are not sampled at random unless the queue includes a random stratum (include one).
5. **Uses of sparse labels** (never penalising unknown): (a) tune guard policy against masked labels, score = precision/recall over labelled cells only, negatives from state `no`; (b) train/validate detectors on labelled cells; (c) reweight which frontiers to prune; (d) **human-verified GOOD cells are protected**: the guard may not prune `good_sheet=yes` cells (extension of D3), and unknown is never treated as bad.

## 3. Overlay inventory (exists vs needs computing)
Per vertex: material/CT support (`score` sampler, `segment_yield` material_frac sampled; per-vertex map to compute), vacuum, fold, planarity (`geomaps.planarity_score` is per-sheet; local version = `plan` mask), quad flip, stretch, wrap spacing, curvature, ridge hit, seam, normal deviation vs normal grid, empty space, roughness (segment-level scalar, per-vertex = frontier cells), selfx contact (transverse / coplanar / grazing: in the selfcross report, per-site), hairpin (`geomaps.fold_metrics`: lines, per-line), round of growth (`generations.tif`), prune-reason colours (`guard_reasons_r<N>.npz`), surface-prediction confidence (nnU-Net m7 zarr, sample at vertex: to compute), fibre/mushy (`fibre_metrics`, render-space: to map back), local texture / ink score per family (ink maps live in render/UV space: needs UV-to-vertex map), distance to nearest other wrap (`wrap_spacing` mask gives flag; distance value to compute), flatten distortion (UV stretch / area ratio: `geomaps.jacobian` / `anisotropy`, flatten output).
Per sheet (metric names in `metric` table / `rounds.jsonl`): verified_cm2, area_cm2, material_frac (+bbox_occupancy control), onesheet_frac, geo_fold_frac / geo_hairpin_lines / geo_lines_read (hairpin ratio), selfcross density (`guard_summary.selfcross_*`), hole_frac / n_holes (`shape_metrics`), geo_planarity, geo_squareness, same-sheet overlap with other segments (`coverage` covered_frac), ink families count, flags (nofinish, paused, pause_reason).

## 4. Where it plugs into cloud-grow
`cloud-grow` exports `guard_reasons/*.npz`, `rounds.jsonl` and tifxyz checkpoints, which are everything the proposal pre-fill needs; the importer registers nothing about labels (labels are hub-side, human-made, never required for import).
